# Методология тестирования

При разработке прогонялся набор из 5 категорий вопросов на реальной (на тот момент —
непубличной) базе знаний:

1. Фактический вопрос с прямым ответом в источнике
2. Вопрос, требующий синтеза информации из нескольких документов
3. Вопрос об ограничениях/политиках системы
4. Вопрос, требующий актуального контекста (например, про инцидент/статус)
5. Вопрос **вне** базы знаний — проверка честного отказа отвечать вместо выдумывания факта

Для текущей (публичной) базы знаний — README открытых проектов автора — результаты
этих тестов нужно снять заново: содержимое источников другое, поэтому старые
вопросы/ответы к нему не относятся. Тестовый скрипт можно написать по аналогии,
например:

```bash
python3 query.py "Какие security-хуки есть в public-architecture-claude-code?"
python3 query.py "Как работает многоуровневая память в jarvis-telegram-gateway?"
python3 query.py "Сколько стоит подписка на этот сервис?"   # нет в базе — должен честно отказаться
```

## Оценка качества (roadmap)

Изначально оценка делалась вручную (сверка ответа с источником). В `Roadmap` в
README отмечена задача подключить автоматическую оценку через
[RAGAS](https://github.com/explodinggradients/ragas) (Faithfulness, Context Precision)
— как это уже сделано в родственном проекте [`rag-docs-assistant`](../rag-docs-assistant)
автора.
